## 📌 Overview

The `models` module defines the relational database schema and Object-Relational Mapping (ORM) classes for the **Industrial Edge AI Energy Optimization Module** using SQLAlchemy[cite: 6]. It structures multi-tenant client entities, industrial hardware devices, real-time telemetry sensor streams, and automated anomaly alert logs[cite: 6].

---

## 📂 File Structure & Components

```text
app/models/
├── __init__.py     # Package initializer
└── models.py       # SQLAlchemy ORM models (Client, Device, SensorData, Alert)
```

## 🔍 Detailed Model Breakdown (`models.py`)

### 1. `Client` Model (`clients` table)

- **Purpose:** Manages system users/clients with multi-tenant data segregation.
- **Key Columns:**
- `id`: Primary key identifier.

- `client_id`: Unique string identifier for tracking and token binding.

- `company_name`: Unique name of the industrial client or organization.

- `contact_email`: Optional email for client correspondence.

- `hashed_password`: Securely hashed credentials using bcrypt.

- `is_active`: Boolean flag indicating operational status (supports soft deletion).

- `deleted_at`: UTC timestamp recording when a soft deletion occurred.

- **Relationships:** One-to-many relationship linking to `Device`.

### 2. `Device` Model (`device` table)

- **Purpose:** Represents industrial monitoring hardware units deployed at client sites.
- **Key Columns:**
- `id`: Primary key identifier.

- `device_serial`: Unique serial number for hardware verification.

- `hardware_model`: Specification of the hardware device.

- `client_id`: Foreign key linked to `clients.id` enforcing strict tenant isolation.

- `is_active` & `deleted_at`: Status flags supporting soft deletion and hardware retirement.

- **Relationships:**
- Belongs to a `Client`.

- Has many `SensorData` records and system `Alert` logs.

### 3. `SensorData` Model (`sensor_data` table)

- **Purpose:** Stores high-frequency operational telemetry streamed from hardware devices.
- **Key Columns:**
- `id`: Primary key identifier.

- `device_id`: Foreign key linked to `device.id`.

- `power_kw`: Actual recorded power consumption ($E_{actual}$) in kilowatts.

- `temperature_c`: Operating temperature in Celsius.

- `voltage`: Optional voltage telemetry reading.

- `optimal_baseline`: Predicted optimal energy baseline ($E_{optimal}$) generated by the AI engine.

- `is_anomaly`: Boolean flag indicating whether energy waste or an anomaly threshold was breached.

- `created_at`: Automatic UTC timestamp marking the reading time.

- **Indexing:** Features a composite index (`idx_device_created_at`) across `device_id` and `created_at` to optimize time-series queries.

- **Relationships:** Belongs to a `Device`.

### 4. `Alert` Model (`alerts` table)

- **Purpose:** Logs system warnings and deviation checkpoints when energy waste exceeds safe tolerances.
- **Key Columns:**
- `id`: Primary key identifier.

- `device_id`: Foreign key linked to `device.id`.

- `deviation_value`: Quantified magnitude of the energy waste deviation.

- `created_at`: Automatic UTC timestamp when the alert was triggered.

- **Relationships:** Belongs to a `Device`.
